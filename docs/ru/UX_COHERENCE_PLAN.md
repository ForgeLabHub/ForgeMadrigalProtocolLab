# План согласованности UX

Английский оригинал: [UX_COHERENCE_PLAN.md](../UX_COHERENCE_PLAN.md).

Три открытых pull request'а добавляют по способу подсказать что-то читателю,
впервые открывшему окно. Они пересекаются, и если взять их как есть, на одном
окне окажется больше одного приветствия и больше одной полосы с инструкцией. Эта
заметка фиксирует согласованную роль каждой части и порядок их вливания, чтобы в
итоге остались один стартовый экран и один контекстный тренер, а не стопка
конкурентов.

## Части

| Часть | Где | Что это | Роль |
| --- | --- | --- | --- |
| `guide_panel.py` | в `main` | полоса из четырёх шагов над рабочим пространством, включена всегда, пока рабочий процесс не пройден | текущая; её четыре шага повторяют воркфлоу второй раз |
| `welcome_view.py` | PR #65 (`ux/full-overhaul`) | полноэкранный стартовый экран в `QStackedWidget`, показывается, пока захват не открыт | **стартовый экран** |
| `start_screen.py` | PR #63 (`ux/empty-state`) | второй полноэкранный стартовый экран с теми же кнопками «Открыть пример / Открыть файл» | дубликат экрана из #65 |
| `guided.py` (`GuidedPanel`) | PR #66 (`ux/guided-mode`) | пятишаговый тренер простым языком над рабочим пространством | **контекстный тренер** |

## Замысел

Читатель встречает ровно по одному экземпляру каждого:

1. **Пока захват не открыт — один стартовый экран.** Заголовок, один вопрос и
   два способа на него ответить: *Открыть пример* и *Открыть файл…*. Это
   `welcome_view` из PR #65 (равноценно `start_screen` из #63; идея одна,
   поэтому остаётся один). Больше на экране ничего нет: ни полосы
   руководства, ни тренера.

2. **После открытия захвата — один контекстный тренер.** Одна полоса над
   рабочим пространством, которая называет текущий шаг и следующее действие
   простыми словами, скрывается после завершения воркфлоу и может быть
   отключена навсегда в настройках. Это `GuidedPanel` из PR #66.

3. **Текущий `GuidePanel` выводится из эксплуатации.** Он говорит те же четыре
   шага, что и тренер, поэтому держать оба — это и есть проблема дублирующихся
   панелей. Его полезные части — машина состояний воркфлоу и отметки «шаг
   выполнен / следующий / в очереди» — живут дальше в тренере и на стартовом
   экране.

## Почему стартовый экран достаётся #65, а не #63

Оба строят стартовый экран из одной идеи; оба не нужны.

* #65 **MERGEABLE / CLEAN** относительно текущего `main`; #63 **CONFLICTING**
  относительно базы, отставшей на три вливания (`d156a77`), поэтому #63 нужно
  перебазировать, прежде чем он вообще сможет влиться.
* В #65 уже есть соответствующий английский каталог строк и диалог выбора
  корпуса; в #63 их нет.
* При этом в #63 есть одна вещь, которую стоит взять: его сигнатура
  `set_progress(capture, session, rule)` — аккуратный контракт для стартового
  экрана. В #65 эквивалентная `set_progress(*, capture, session, rule)`.

Решение: оставить **#65**; #63 закрыть как заменённый либо перебазировать только
ради деталей, которых нет в #65 (таких не найдено).

## Почему тренер заменяет полосу, а не встаёт рядом с ней

PR #66 добавляет `GuidedPanel`, но оставляет `GuidePanel` подключённым, поэтому
окно показывает **оба** одновременно (замерено: тренер ~124 px плюс полоса
~86 px, вместе ~210 px из окна в 768 px). Это ровно тот исход «дублирующихся
панелей с инструкциями», которого нужно избегать. #66 должен убрать
`GuidePanel` из центральной раскладки, когда присутствует тренер.

## Порядок вливания (без механического слияния)

Интеграция выполнена в ветке `ux/integration`, собранной из `ux/full-overhaul`
(PR #65) со влитым PR #67 (`ux/overhaul`). В #67 тренер уже принят и
`guide_panel` удалён, поэтому он заменяет собой шаг «#66, перебазированный на
#65», описанный выше; формулировки #66 сохранились внутри `guided.py`.

1. **Сначала #65** (стартовый экран + диалог корпуса + расширенный конструктор
   правил + английский каталог). Он был чистым на `main` и даёт экран первого
   запуска.
2. **Затем #67 поверх**, с сохранением его пятишагового тренера, его
   переключателя в настройках и исправлений запускаемых правил, и с удалением
   старой полосы `GuidePanel`, чтобы осталась одна панель инструкции.
3. **#63 остаётся открытым**, пока ревьюер не одобрит закрытие: его
   `start_screen.py` — та же идея, что `WelcomeView` из #65, на более старой
   базе, без английского каталога и без диалога корпуса, то есть он заменён. Не
   закрывать без этого одобрения.
4. Собственные доработки аудита (D1 — запускаемое правило, D3 — применённое
   состояние) покрыты здесь переработкой потока правил в #67 вместе с
   регрессионными тестами `tests/ui/test_rule_build_flow.py`; D2 (язык
   подсказок) покрыт перестройкой пустого состояния при смене языка.

Номер шага тренера выводится из того, что открыто (захват, сессия, правило,
применено), а не из истории кликов, поэтому он всегда соответствует реальному
прогрессу — это `MainWindow._guided_index`, и именно это поведение нужно
сохранить.

# Карта модулей: что заимствовать в другой проект

Английский оригинал: [module-map.md](../../modules/module-map.md).

Таблица отвечает на вопрос «что взять, если нужно X»: минимальный набор файлов,
зависимости и что придётся заменить. Спецификации модулей — в
[capture.md](capture.md) и [protocol.md](protocol.md).

## Правила переноса

1. Ядро (`capture`, `protocol`, `hypothesis`, `project`, `report`) не зависит от Qt и
   сети: его можно забрать целиком и проверить `make test-core` без графики.
2. Внешняя система всегда за адаптером: `dpkt` изолирован в `parser.py`, файловое
   хранилище — в `project/storage.py`; заменяется реализация, а не вызывающий код.
3. Инвариант «факт ≠ гипотеза» — часть контракта: результат применения правила
   содержит статус и привязку к байтам, поэтому его нельзя «улучшить» молча.
4. Тесты — часть модуля: на каждый модуль есть каталог в `tests/` с тем же именем.
5. Настройки приложения — один диалог и один набор ключей
   ([docs/SETTINGS.md](../SETTINGS.md)), без «магических» переменных окружения.
